# 管理后台 技术方案

> 目标: 为 lhlord 提供不依赖数据库客户端的数据表管理能力, 覆盖表结构维护, 数据增删改查与只读 SQL 调试 
> 实现位置: `backend/src/routes/tables.js`, `backend/src/routes/debug.js`, `frontend/src/App.vue`, `frontend/src/views/TableData.vue` 

## 1. 功能目标

- 表结构管理: 表列表, 新建数据表, 查看表结构, 新增字段, 修改字段, 删除字段, 删除前的字段影响分析 
- 数据管理: 分页查询与模糊搜索, 新增, 编辑, 删除, 批量导入, 导出 CSV/JSON 
- 只读 SQL 调试: 切换数据库, 执行只读语句, 展示列名, 行数与结果集 
- 面向 `backend/database/` 中脚本建立的业务表, 不依赖 ORM 模型 

## 2. 技术路线

- 后端以 Express Router 提供两组接口, 分别挂载到 `/api/tables` 与 `/api/debug` 
- 数据库访问复用 `backend/src/db.js` 的 mysql2 连接池, 连接池已开启 `namedPlaceholders` 
- 表结构信息实时读取 `information_schema`, 不维护本地元数据副本, 手工执行 DDL 后界面立即生效 
- 前端 Vue3 + Element Plus, axios 实例 baseURL 固定为 `/api`, 开发期由 Vite 代理到后端 7100 端口 
- 页面划分: `App.vue` 负责模块导航, 表列表, 新建表与调试抽屉; `TableData.vue` 负责单表的数据与结构维护 

## 3. 实现原理

### 3.1 元数据驱动

`getTableMeta()` 是所有表操作的前置步骤: 先用 `^[A-Za-z0-9_]+$` 校验表名, 再查 `information_schema.tables` 判断表是否存在(缺失返回 404), 最后按 `ORDINAL_POSITION` 读取 `information_schema.columns` 的列名, 列类型, 数据类型, 是否可空, 键类型, 默认值, `EXTRA` 与注释, 并把 `COLUMN_KEY = 'PRI'` 的第一列作为主键 

### 3.2 标识符与类型白名单

- 表名与字段名都做正则白名单校验 
- 字段类型限制在 `TYPE_WHITELIST` 内(BIGINT 至 JSON), 长度仅对 CHAR, VARCHAR, DECIMAL 生效 
- 标识符无法参数化, 拼接时统一用反引号包裹; 值一律通过占位符传参, 注释等字符串做单引号双写转义 

### 3.3 DDL 生成

- 新建表: 由字段定义拼接 `CREATE TABLE IF NOT EXISTS`, 引擎与字符集固定 InnoDB 与 utf8mb4/utf8mb4_unicode_ci, 标记自增的字段自动作为主键 
- 新增字段: `ALTER TABLE ... ADD COLUMN`, 自增字段同时追加 `ADD PRIMARY KEY` 
- 修改字段: 先把 `information_schema` 中的原始定义与请求覆盖项合并, 再生成完整列定义提交 `ALTER TABLE ... CHANGE`, 避免改名或改类型时丢失默认值, 注释与 `ON UPDATE` 属性 
- 删除字段: 主键字段直接拒绝 

### 3.4 字段影响分析

项目不建物理外键, 关联关系以注释中的逻辑外键表达, 因此 `GET /api/tables/:table/columns/:column/refs` 从两个方向给出影响面: 其他表中的同名字段, 以及注释中包含 `表名.字段名` 的字段 
界面在删除字段前调用该接口提示影响范围, 是否继续由使用者判断 

### 3.5 数据读写

- 可写列由 `getWritableColumns()` 计算: 排除自增列与 `create_time`/`update_time`, 更新时额外排除主键 
- 查询参数为 `page`, `pageSize`, `search`, `field`, 其中 pageSize 上限 200 
- 未指定 field 时对所有字符类型列做 `LIKE` 模糊匹配, 指定 field 时只匹配该列; 排序固定按主键倒序 
- 空字符串统一转为 null, 由数据库决定最终默认值 
- 批量导入单次上限 1000 行 
- 更新与删除必须存在主键, 按主键定位, 影响行数为 0 时返回 404 

### 3.6 调试接口的只读约束

- 调试使用独立连接池(connectionLimit 为 2), 切换数据库不影响管理后台主连接 
- `READ_ONLY_RE` 只放行 SELECT, SHOW, DESCRIBE, DESC, EXPLAIN, USE, WITH, 其余语句返回 400 
- `USE` 语句单独解析, 校验库存在后更新内存中的 currentDb 
- 执行前在连接上先 `USE` 当前库, 返回列名, 行数与结果集; 非结果集语句返回 affectedRows 与提示 

## 4. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/tables | 数据表列表 |
| POST | /api/tables | 新建数据表 |
| GET | /api/tables/:table | 表结构(字段/类型/主键/注释) |
| POST | /api/tables/:table/columns | 新增字段 |
| PUT | /api/tables/:table/columns/:column | 修改字段(改名/类型/可空/默认值/注释) |
| DELETE | /api/tables/:table/columns/:column | 删除字段 |
| GET | /api/tables/:table/columns/:column/refs | 字段影响分析(同名字段/逻辑外键引用) |
| GET | /api/tables/:table/data | 表数据(分页 + 模糊搜索) |
| POST | /api/tables/:table | 新增记录 |
| POST | /api/tables/:table/import | 批量导入记录 |
| PUT | /api/tables/:table/:id | 按主键更新记录 |
| DELETE | /api/tables/:table/:id | 按主键删除记录 |
| GET | /api/debug/databases | 可用数据库列表 |
| POST | /api/debug/use | 切换调试数据库 |
| POST | /api/debug/query | SQL 调试(仅只读语句) |

## 5. 前端实现

- `App.vue`: 顶部模块 tab(炼丹系统/管理后台), 表列表侧栏, 新建表对话框(字段行可动态增删), SQL 调试抽屉, 亮暗主题切换并写入 localStorage 
- `TableData.vue`: 头部提供表结构, 搜索(可指定字段), 导出 CSV/JSON, 导入, 新增与刷新; 表格支持行内编辑与删除; 编辑对话框按字段类型切换控件(开关/数字/日期/文本); 表结构抽屉负责字段维护 

## 6. 约束

- 所有表操作限定在 `DB_NAME` 指定的库内 
- 接口无鉴权, 服务仅监听 127.0.0.1, 定位为本地开发工具, 不适用于公网部署
