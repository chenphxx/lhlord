# 玩家端 技术方案

> 目标: 提供本地单机的修行闭环(开局创建修士, 探索, 闭关, 突破), 并把炼丹系统接入玩家真实背包与成长 
> 实现位置: `backend/src/routes/game.js`, `backend/database/schema/game.sql`, `frontend/src/views/GameView.vue`, `frontend/src/views/AlchemyView.vue` 
> 关联文档: [数据库设计](数据库设计.md), [炼丹系统](炼丹系统.md), [境界](../背景信息/境界.md) 

## 1. 功能目标

- 单存档: 固定 `save_id = 1`, 一个本地存档位, 前台玩家端与管理工具分离 
- 开局: 输入道号创建修士, 同时创建修炼属性, 丹修能力与开局物品 
- 探索: 消耗一日, 获得当前境界可得的草药与灵石 
- 闭关: 消耗一日积累修为, 每日收益由资质与修炼增益决定 
- 突破: 修为达到门槛后按成功率冲击小境界, 三个小境界圆满后进入下一境界 
- 见闻: 每次行动写入事件记录, 玩家端按时间倒序展示 
- 炼丹衔接: 玩家端炼丹房复用炼丹系统接口, 消耗与产出一律落在存档角色的真实背包, 丹炉限于已持有 

## 2. 技术路线

- 后端以 Express Router 提供玩家端接口, 挂载到 `/api/game`, 与炼丹, 管理后台路由并列 
- 涉及改数的行动(开局, 探索, 闭关, 突破)使用连接级事务, 读取存档时 `FOR UPDATE` 锁行, 异常统一回滚 
- 数值公式集中在 `game.js` 内, 状态接口与结算接口共用同一组函数, 避免前端重复实现造成数值漂移 
- `GET /api/game/state` 一次性返回角色, 修为进度, 灵石, 天数, 背包, 生效增益与见闻, 前端单次请求即可渲染整个修行台 
- 前端 `GameView.vue` 单文件实现开局页与修行台, 炼丹房直接复用 `AlchemyView.vue` 的玩家模式 

## 3. 实现原理

### 3.1 存档模型

- `game_save` 保存玩家角色, 当前小境界, 当前修为, 灵石与已度过天数, 通过 `character_id` 逻辑关联 `character` 
- `game_event` 保存玩家端见闻, 字段为事件类型, 标题与描述, 前端按类型着色 
- 角色数值沿用既有表: 资质与悟性来自 `character_attribute`, 背包来自 `character_inventory`, 丹药增益与丹毒来自 `character_buff` 与 `character_drug_toxin`, 丹修能力来自 `character_alchemy_skill` 
- 开局在 `character` 写入境界 `炼气`, 职业 `气修`, 人族人属, 并写入属性行, 丹修能力行与开局物品(活血草, 生息花, 玉露草各 8, 一级炼丹炉 1) 

### 3.2 数值

- 小境界修为门槛: `100 * realm_level * stage`, `realm_level` 为位面内境界序号, `stage` 取 1 至 3 
- 每日修为: `20 + 资质 * 2`, 再乘以免药增益系数 
- 突破成功率: `65 + 资质 * 0.5 + 悟性 * 0.25 + 突破丹药加成`, 上限 95 
- 探索产出: 草药取当前境界可得等级内随机一种, 数量 2 至 4, 灵石在 12 至 20 之间随机 

### 3.3 行动结算

- 探索: 锁定存档后随机取一味不超过 `realm_level + 1` 且不高于 3 级的草药, 累加灵石与天数, 背包按 `(character_id, item_id)` 唯一键累加数量 
- 闭关: 读取存档与生效的 `CULTIVATION_UP` 增益, 按每日修为结算并累加天数 
- 突破: 修为不足直接返回 400 并给出缺口; 成功时小境界加一, 三个小境界圆满则按 `(realm_world, realm_level + 1)` 取下一境界, 修为清零; 失败时修为损失约四分之一 
- 每次行动都写入一条 `game_event`, 状态接口只返回最近 12 条 

### 3.4 与炼丹系统的衔接

- 玩家端炼丹房把存档角色作为 `characterId` 与 `inventoryCharacterId` 传给 `/api/alchemy/*`, 因此炼制扣减的草药, 消耗的丹炉耐久与产出的丹药都落在玩家真实背包 
- `AlchemyView.vue` 新增 `playerCharacterId` 与 `ownFurnaceIds` 两个属性: 传入角色后进入玩家模式, 隐藏修士选择与丹炉品质编辑, 命牌属性只读, 丹炉列表收敛为背包中已持有的丹炉 
- 玩家模式炼制成功后抛出 `crafted` 事件, `GameView.vue` 据此重新拉取存档, 背包与增益立即同步 
- 丹药对成长的作用复用既有接口: `POST /api/alchemy/use-pill` 写入 `character_buff`, 玩家端读取 `CULTIVATION_UP` 提升每日修为, 读取 `BREAKTHROUGH_BONUS` 提升突破成功率 

### 3.5 前端实现

- 开局页: 玄墨底纹与朱砂印记, 输入道号后调用开局接口, 已存在存档时直接进入修行台 
- 修行台: 左侧修士命牌固定展示道号, 境界, 修为进度, 根骨与生效增益; 右侧为境界天梯, 三个行动入口, 行囊与修行见闻 
- 境界天梯: 按 `GET /api/game/realms` 返回的当前位面境界绘制, 已过境界, 当前境界与未达境界区分配色, 当前境界下方的小境界刻度反映前中后进度 
- 行囊: 支持全部, 草药, 丹药, 丹炉筛选, 丹药可直接服用, 服用后刷新存档 
- 主题: 复用 `styles/theme.css` 的玄墨, 月白, 翠玉, 朱砂, 鎏金令牌, 亮暗两套主题共用同一组语义变量 

## 4. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/game/state | 存档状态(角色, 修为, 灵石, 背包, 增益, 见闻) |
| GET | /api/game/realms | 全部境界, 供境界天梯绘制 |
| POST | /api/game/start | 开局创建修士并发放初始物品 |
| POST | /api/game/cultivate | 闭关一日, 积累修为 |
| POST | /api/game/explore | 探索一次, 获得草药与灵石 |
| POST | /api/game/breakthrough | 尝试突破当前小境界 |

## 5. 约束与已知限制

- 接口无鉴权, 服务仅监听 127.0.0.1, 定位为本地单机原型 
- 仅一个存档位, 开局后不可重置, 重置需要清理 `game_save` 与 `game_event` 
- 丹炉耐久记录在 `alchemy_furnace` 的物品定义行上, 多个角色共用同一丹炉定义, 玩家端与炼丹系统模拟器会互相消耗耐久, 后续拆出物品实例表后再分离 
- 灵石当前只有产出没有消耗途径, 战斗, 宗门经营与功法系统尚未实现, 属于后续扩展范围
