# 炼丹系统 技术方案

> 目标: 实现丹方匹配, 自由配药, 批量炼制, 丹药使用与灵田种植的完整闭环 
> 实现位置: `backend/src/routes/alchemy.js`, `frontend/src/views/AlchemyView.vue` 
> 关联文档: [数据库设计](数据库设计.md), [炼丹机制概述](../背景信息/炼丹.md) 

## 1. 功能目标

- 数据面: 丹方与丹方槽位, 丹炉, 角色炼丹属性, 角色背包, 丹药 buff, 丹毒, 灵田, 炼丹批次日志 
- 炼制入口: 选择丹方后自动配药; 不选丹方时自由配药并反查匹配的丹方 
- 结果判定: 药力覆盖, 药引温度平衡, 品阶稳定度, 跨级风险, 丹炉耐久消耗 
- 丹药使用: 扣减丹药, 写入 buff, 累积丹毒 
- 灵田: 种植草药与到期收获 

## 2. 技术路线

- 后端在 Express Router 内实现全部算法, 挂载到 `/api/alchemy`, 计算过程不写入数据库, 也不使用存储过程 
- 涉及改数的流程(炼制/服用/种植/收获)使用连接级事务, 必要时 `FOR UPDATE` 锁行, 异常统一回滚 
- 试炼预览与正式炼制共用同一套计算函数, 差异只在随机扰动与是否落库 
- 前端 `AlchemyView.vue` 单文件实现丹房与背包两个 tab, 参数变化通过 watch 触发 250ms 防抖后请求试炼预览 

## 3. 实现原理

### 3.1 药力模型

- 单株药力 `basePower(level) = 10 * 2 ^ (level - 1)`, 药材药力为单株药力乘以数量 
- 丹方槽位分 main(主药), secondary(辅药) 与 guide(药引), 每个槽位声明 `effect_code` 与 `required_power` 
- 主药与辅药按药材的 `main_effect`/`secondary_effect` 匹配药性, 药引按 `guide_effect` 提供温度符号: 性寒为 -1, 性热为 1, 其余为 0 

### 3.2 自动配药

`autoPlan()` 以背包剩余库存为准逐槽位取药: 

- 主药与辅药在药性匹配的药材中按等级升序取用, 单味药不足时依次取下一味, 直到满足 `required_power * batchCount` 
- 药引先计算非药引药材的温度总和, 与容差比较后确定目标符号(偏热取性寒, 偏寒取性热, 在容差内取中性), 再按符号匹配优先, 等级升序的顺序取用到引药需求药力 
- 任意槽位库存不足时返回 400, 并指出缺失的药性 

### 3.3 结果判定

`calculateOutcome()` 是核心判定函数: 

- 覆盖度: 逐槽位比较实际药力与 `required_power * batchCount`, 任一槽位不足即视为未覆盖 
- 温度与平衡: 药引温度符号累计, 容差取 `max(20, 需求药力 * 0.04)`, 平衡度为 `clamp(1 - |温度| / 容差, 0, 1)` 
- 稳定度: `50 + 30 * 平衡度 + 丹炉匹配 + 炼丹匹配 + 火候匹配 + 丹炉热稳 - 20 * 溢出率 - 跨级风险 + 随机扰动`, 结果限制在 0 至 100 
- 等级匹配项都由各自等级与丹药等级的差值截断后加权, 跨级风险在跨 1 级时为 15, 跨 2 级及以上为 35, 溢出率为药力超出需求的比例 
- 品阶映射: 未覆盖为药渣; 稳定度低于 20 时跨级炸炉, 同阶药渣; 低于 40 废丹; 低于 60 下品; 低于 80 中品; 低于 90 上品; 其余极品 
- 耐久消耗: 同阶每次 1 至 2 点, 跨 1 级 40 点, 跨 2 级 80 点, 跨 3 级及以上返回 Infinity 并拒绝炼制 
- 试炼预览的随机扰动固定为 0, 正式炼制的扰动取 -5 至 5 

### 3.4 自由炼丹

- 未提供药材时按丹方自动配药; 提供药材时先补齐物品的等级与药性, 再按主药, 辅药, 药引的顺序定位槽位 
- 未选丹方时用 `findRecipeForSelected()` 反查可匹配的丹方, 反查不到则走 `buildFreeResult()`, 只按药引平衡与炼丹, 火候等级估算, 产物为药渣或废丹 

### 3.5 落库与副作用

- `POST /api/alchemy/craft` 在同一事务内完成: 扣减背包药材(下限 0), 扣减丹炉耐久, 写入 `alchemy_batch` 批次记录(输入与输出 JSON, 温度, 平衡度, 稳定度, 结果, 品质, 数量), 成丹时把丹药写入背包并累加 `character_alchemy_skill` 的成功次数与最佳丹方等级 
- `POST /api/alchemy/use-pill`: 扣减丹药数量, 写入 buff, 累积 `character_drug_toxin` 
- `POST /api/alchemy/fields/plant`: 校验灵田空闲且物品为草药, 扣 1 个种子, 按草药等级设置生长天数与产量 
- `POST /api/alchemy/fields/harvest`: 加锁读取灵田, 校验已成熟后把产量写入背包并清空灵田 

### 3.6 前端实现

- 丹房 tab: 修士命牌(角色选择与属性编辑), 丹炉面板, 选药面板, 炼制面板与当前丹毒展示 
- 试炼预览: 监听角色, 丹方, 丹炉, 批量数与所选药材, 250ms 防抖后调用试炼接口 
- 药架: 支持分类与等级筛选, 模糊/精确搜索与分页; 药材可替换, 替换候选只展示同药性药材 
- 背包 tab: 使用固定模拟角色(2)的独立背包, 不随左侧角色切换, 炼制结果回写该模拟背包 
- 后端已提供丹药使用, buff 查询, 批次日志与灵田接口, 当前前端只接入炼制与背包相关部分 

## 4. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/alchemy/overview | 角色/丹方/丹炉总览 |
| GET | /api/alchemy/characters/:characterId | 角色详情(含炼丹属性与丹毒) |
| PUT | /api/alchemy/characters/:characterId/attributes | 保存角色属性 |
| PUT | /api/alchemy/furnaces/:itemId | 保存丹炉品质与热稳 |
| GET | /api/alchemy/recipes | 丹方与槽位 |
| GET | /api/alchemy/inventory | 背包 |
| GET | /api/alchemy/fields | 灵田 |
| GET | /api/alchemy/plan | 按丹方自动配药的试炼预览 |
| POST | /api/alchemy/plan | 自由配药的试炼预览 |
| POST | /api/alchemy/craft | 正式炼制并落库 |
| POST | /api/alchemy/use-pill | 服用丹药 |
| GET | /api/alchemy/buffs | 角色 buff 与丹毒 |
| GET | /api/alchemy/logs | 最近 50 条炼丹批次 |
| POST | /api/alchemy/fields/plant | 种植草药 |
| POST | /api/alchemy/fields/harvest | 收获草药 |

## 5. 约束

- 接口无鉴权, 服务仅监听 127.0.0.1, 定位为本地开发工具 
- 批量数与服用数量都做上限收敛, 批量上限 99, 服用上限 999 
- 机制与数值以 [炼丹机制概述](../背景信息/炼丹.md) 为准, 本文只描述实现方式
